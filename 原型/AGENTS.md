# 原型维护规则

1. 先读 README.md，再在模块索引.md 用业务名称或函数名定位；只读取和修改相关源文件。
2. 不读取或编辑生成文件 assets/app.js、index.html，也不重新读取上级原始巨型 HTML，除非明确需要与原版比较。
3. src/modules 中的文件共享原版闭包作用域；manifest.json 的顺序不能随意调整。新增文件须显式登记到对应顺序位置。
4. 样式按 styles 的编号顺序覆盖。不要为无关模块添加全局选择器。
5. 修改后执行 node build.mjs；它会检查最终脚本语法和资源完整性。涉及交互时再做相应后台浏览器验证。
6. 默认交付本地文件，不使用 Sites，不发布网站，不自动打开浏览器或预览面板。
7. 保持文件职责清晰；跨模块重构需核对后续函数覆盖和初始化依赖，不能靠重新排列脚本实现。

8. 日常先看维护指南.md，通过node dev.mjs locate定位当前责任入口和加载顺序中的覆盖候选；避免猜路径及读取整包生成文件。
9. 交互验证先使用dev.mjs check对应范围，一次启动一个后台浏览器；失败后只重跑失败范围。all仅覆盖已登记检查，图片、草稿、目标与计算边界仍需对应专项验证。outputs中的旧测试选择器不作为当前页面事实。
