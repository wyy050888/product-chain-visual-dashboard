# 维护入口与验证范围

当前是本地前端原型，直接打开index.html；不要修改生成文件。
日常先用本文件和dev/areas.json定位，README后半段保留历史记录，不能把旧记录当最新规范。

## 常用命令

在原型目录运行，Node不可用时使用Codex内置Node：

| 任务 | 命令 |
| --- | --- |
| 查功能入口、源码引用和覆盖候选 | node dev.mjs locate 筛选 或 node dev.mjs locate qrOpenList |
| 查看模块规模 | node dev.mjs audit |
| 构建 | node dev.mjs build |
| 页面基础检查 | node dev.mjs check smoke |
| 全局表格列宽、固定列及保存恢复 | node dev.mjs check columns |
| 筛选改动检查 | node dev.mjs check filters |
| 六榜字段、表头、趋势改动检查 | node dev.mjs check risk |
| 运行全部已登记自动检查 | node dev.mjs check all |
| 保存源文件后自动构建 | node dev.mjs watch |

check使用后台浏览器，不打开预览。一个命令只启动一个浏览器、加载一次页面。
需要Playwright；内置Node会自动找到同包依赖。其他环境可设置DASHBOARD_PLAYWRIGHT_PATH、DASHBOARD_BROWSER_PATH。
watch是前台开发命令，Ctrl+C停止；本任务不会替用户启动常驻服务。

## 修改边界

- 品牌、类目多选交互和摘要：product-filters/00-multiselect.js。
- 产品筛选取值和匹配：product-filters/01-model.js；季品/产品类型：00-categories.js。
- 六榜本地筛选与店铺匹配：risk-presentation/03-filters.js；分页/表头/行：04-lists.js；原值排序：03-sort.js。
- 卡片标题与筛选分行：risk-card-filters/01.js；平台评分名称：risk-presentation/01-fields.js。
- 亏损榜展示：risk-presentation/01-loss.js、02-loss-card.js、styles/43-loss-preview.css；与品质榜共享头部、双行指标、属性标签。
- 退货恶化榜：risk-presentation/01-return.js；复用02-loss-card.js的五指标渲染，样式由40和43维护。
- 库存/呆滞榜：risk-presentation/01-stock.js、02-stock-card.js、styles/45-stock-preview.css；六榜等高由44-risk-card-alignment.css维护。
- 店铺榜试版：risk-presentation/01-shop.js、02-shop-card.js、styles/42-shop-preview.css；复用品质榜头部、序号与指标色。
- 品质榜试版：risk-presentation/01-quality.js、styles/40-quality-preview.css；只作用于品质卡片和完整榜单。
- 卡片身份与指标布局：risk-presentation/02-cards.js、styles/35-risk-reading.css。
- 金额/百分比统一格式：product-filters/04-display.js；不要逐榜复制格式化。
- 多选外观：styles/39-multiselect.css；其他筛选外观：styles/24-filters.css。
- 当前详情、销售、图片等其他入口见dev/areas.json。

这些是责任入口，不是自动推断的完整依赖图。locate列出加载顺序中的定义/覆盖候选，包装、分支仍需读实际代码。
样例数据、业务规则、公共组件、页面渲染保持分开。已有多个脚本片段，继续拆小文件并不能解除共享作用域。

## 验证边界

先构建，再跑受影响范围。文字或CSS小改动不重复跑全部业务流程；复杂数据/状态改动才补专项验证。
smoke只查首页六榜、列表入口、公共筛选、表格外框和关闭。
filters查品牌并集、品牌/类目组合、Tab保留、重置、窄屏菜单及Escape隔离。
risk查六榜表头/行一致、趋势与类目名称，以及抽屉数值三态排序、跨页排序、偏离勾选、重置、Tab保留和库存明细排序。
period检查跨月/跨年/闰日聚合、上架前零值、目标变更快照、季度文案及年份切换耗时。
all只表示以上已登记检查全部通过，不代表整个产品的完整验收。
detail检查完整榜单与产品详情日期继承、独立切换、逐层返回、草稿保留、三指标趋势及窄屏布局；同时检查退货日周月加权聚合、违规平台/风险类型过滤和待办角色、下发、退回、验收、刷新持久化闭环。
图片、目标和金额边界仍需要对应专项检查；dev工具会打印未覆盖项。
outputs内旧检查脚本属于历史记录，未登记前不要直接复用旧选择器。
检查失败后只重跑失败范围；修正测试选择器不改业务来迎合测试。

## 后续结构治理

优先在需要修改的功能内合并重复覆盖，逐步让每个功能只有一个实现入口。
不要一次性迁移全项目到新框架或调整manifest顺序；共享变量、包装函数和本地草稿需要先确认。
后续新增功能先登记到areas.json和模块索引，避免继续追加临时覆盖文件。

年份性能入口：统一台账由 `unified-product/01-aggregates.js` 按月缓存前缀和，明细按需展开；首页六榜由 `risk-presentation/02-render.js` 一次生成，指标说明复用当次计算结果。不要再包装旧渲染链逐层覆盖卡片。

项目红绿灯全景：总看板入口 `project-panorama/`，样式50，交互检查 `node dev.mjs check projects`。根因/责任人只用显式riskLedger，不读取生成风险模板；第7列台账字段未确认，当前6列。详见根目录交接第15节。

## 首屏加载状态

- 独立模板、样式和启动检测位于 src/boot，由 build.mjs 内联到页面，在主业务脚本下载前生效。
- startup/02-render.js 在首屏同步渲染完成后发送 dashboard:ready；不要用固定延时替代真实完成信号。
- 加载用时较长或脚本下载失败时提供重新加载，完成后移除骨架和交互限制。
- 后台验证：在项目根目录运行 node deploy/check-loading.mjs；覆盖慢加载、失败重试、手机布局和基础交互。

## 共用筛选维护约束

同一业务概念的枚举及交互由公共字典、组件维护，不按页面复制一套实现。字段取值范围和单选/多选沿用各模块已确认配置，不能以“统一组件”为由扩展业务范围；相同名称但口径冲突的字段先确认。六平台固定为抖音、快手、视频号、天猫、京东、拼多多，销售渠道属于独立维度。日期边界、快捷项及清空由调用参数指定；今日、昨日、本周、本月、本年等快捷项统一使用 dashboardToday 的北京时间当天，禁止用已选结束日或固定样例日期代替今天。

业务提示仅保留公式、统计口径与预警条件，不展示空值、零值和占位符等开发规范。
